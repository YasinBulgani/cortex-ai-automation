ARCHITECTURE & EXECUTION MODEL
================================================================================

Layered Service Architecture:
┌─ Tier 1: Universal Async Service Layer (all endpoints async; RLS enforced)
├─ Tier 2: Caching Layer (HTTP + Redis + event-driven invalidation)
├─ Tier 3: Queue Consolidation (BackgroundTasks + RQ + APScheduler + Outbox)
├─ Tier 4: Rate Limiting & Quota (per-tenant API + AI token budgets)
└─ Tier 5: Audit & Compliance (immutable audit log + request logging)

LLM Orchestration Pattern:
┌─ Tool Registry: Pydantic-based tool definitions with confidence thresholds
├─ Orchestrator Agent: Plan → Execute → Verify → Conditional Replan (max 2)
├─ Hierarchical Context: 5-tier loading (core/domain/project/page/history)
│  └─ Budget: 13k base tokens; fallback to RAG at 80% of model max
├─ Conversation Manager: Persistent session history + checkpoints
└─ Resilience: Circuit breaker per tool; 30s timeout; pool exhaustion defense

Task-Specific Model Routing:
- Test Generation: claude-opus-4 ($0.05-0.15/req)
- QA Orchestration: claude-sonnet-4 ($0.02-0.08/req)
- Security Audit: gpt-4-turbo ($0.05-0.12/req)
- Flakiness Analysis: gpt-4o-mini ($0.002-0.01/req) [COST LEADER]
- Banking Domain: Fine-tuned llama-3.1:70b (self-hosted; $0.001-0.003/req)

Cost Optimization:
✓ Redis caching (5m TTL) saves 20-30% LLM calls
✓ Batch related requests (10-15% savings)
✓ Model selection by task (30-40% savings)
✓ Target: 30-40% monthly LLM cost reduction vs. naive API use

CRITICAL RISKS & MITIGATION
================================================================================

🔴 CRITICAL RISKS:

1. RUNAWAY CONTEXT WINDOW (Probability: HIGH | Impact: HIGH)
   Problem: CrossAgentMemory + multi-turn accumulate 10K+ tokens; exceed limits
   Mitigation:
   ✓ Hard token budget per request (80% of model max)
   ✓ Hierarchical context pruning (drop Tier 4→RAG at budget)
   ✓ Auto-summarize outputs (10-page→1-page)
   ✓ Monthly cleanup cron (delete >30d old)

2. TOOL-CALL PARAMETER INJECTION (Probability: MEDIUM | Impact: HIGH)
   Problem: LLM-generated malicious project_id could read cross-tenant data
   Mitigation:
   ✓ Validate all tool calls against user tenant_id (enforce_rls decorator)
   ✓ Mutation tools require 80%+ confidence + human approval
   ✓ Rate limit tool calls (10/min per user)
   ✓ Audit log all tool invocations (immutable)

3. AGENT STATE CROSS-TENANT LEAKAGE (Probability: LOW | Impact: HIGH)
   Problem: Global cache dict not reset between tenant workflows
   Mitigation:
   ✓ Reset on pipeline.reset() (already implemented)
   ✓ Use tenant_id as cache key prefix (already implemented)
   ✓ Audit test for memory clearing between runs

4. FINE-TUNING DATA PII LEAKAGE (Probability: LOW | Impact: HIGH)
   Problem: Training data includes real customer IBAN/account numbers
   Mitigation:
   ✓ Scrub training data using existing mask_sensitive()
   ✓ Fine-tune only on synthetic/anonymized data
   ✓ Audit dataset before training

5. TOKEN COST RUNAWAY (Probability: MEDIUM | Impact: MEDIUM)
   Problem: Multi-turn + long context + replans cost $1-5/workflow → $10K+/month
   Mitigation:
   ✓ Token budgets per workflow type
   ✓ Cost alerts ($500/day threshold)
   ✓ Prefer mini models for analysis
   ✓ Cache project stats + coverage gaps (24h TTL)

6. LLM HALLUCINATIONS ON BANKING RULES (Probability: HIGH | Impact: MEDIUM)
   Problem: Invalid IBAN formats, incorrect OWASP, hallucinated rules
   Mitigation:
   ✓ Fine-tune on banking domain (20-30% hallucination reduction)
   ✓ Validate generated rules against KnowledgeStore ground-truth
   ✓ Add rule-validation tool
   ✓ Fallback to human review for high-risk rules
