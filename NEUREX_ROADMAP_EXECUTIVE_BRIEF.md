## QUESTIONS & ANSWERS

**Q: Why React Native for mobile instead of Flutter?**  
A: React Native preferred due to (a) web team familiarity with JavaScript/TypeScript, (b) larger ecosystem for QA-specific tools, (c) better offline support (WatermelonDB), (d) Expo managed workflow reduces infrastructure burden. Flutter option available if RN performance issues emerge (low probability).

**Q: What's the biggest technical risk?**  
A: Scaling database to 50K+ users with analytics + real-time chat. Mitigation: connection pooling (Phase 0 ✅ done), read-replica (Phase 3 ✅ done), materialized views (Phase 2), optional data warehouse (Phase 2).

**Q: Can we ship faster (compress timeline)?**  
A: Phases 1 & 2 can overlap by ~6 weeks (parallel mobile + web work). Compressed timeline: 30 weeks instead of 44 weeks (7.5 months). Trade-off: higher team overhead, more QA risk.

**Q: What if LLM adoption is <50% (Phase 4 target)?**  
A: Acceptable fallback: LLM features ship as "beta" tier, not mandatory. Revenue impact: -$2M Y2 (still $14M+ ARR). Can extend learning curve into Year 2.

**Q: What happens if we hit a Phase gate and can't proceed?**  
A: Each phase is independent. We can:
- Pause and iterate (Phase 2 → refine PWA, extend analytics)
- Pivot features (if mobile adoption low, redeploy resources to web)
- Extend timeline (all gates achievable with 2–4 week extensions)

**Q: How do we handle team retention (high-growth hiring)?**  
A: (1) Equity grants (0.1–0.5% per level), (2) competitive salary ($140K–$180K engineers), (3) mentorship program (senior pairs with junior), (4) stock bonuses on phase gates.
