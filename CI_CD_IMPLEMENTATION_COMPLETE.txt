PIPELINE ARCHITECTURE
================================================================================

TRIGGER:
  - Push to: main, develop, feature/qa-system-bootstrap
  - Pull requests to: main, develop
  - Path filters: backend/, apps/web/, e2e/, engine/

STAGES:

Stage 1: UNIT TESTS (Required)
  - Backend: pytest with 70% coverage requirement
  - Engine: Flask unit tests
  - Services: PostgreSQL 16 + Redis 7
  - Time: 3 minutes
  - Artifacts: coverage.xml, HTML report

Stage 2: API TESTS (Required)
  - Contract tests: OpenAPI spec compliance
  - Integration tests: Endpoint functionality
  - Database: PostgreSQL 16 + Redis 7
  - Time: 5 minutes
  - Artifacts: JUnit XML

Stage 3: FRONTEND TESTS (Required)
  - TypeScript: tsc --noEmit
  - ESLint: npm run lint
  - Jest: npm test --coverage
  - Build: npm run build
  - Time: 5 minutes
  - Artifacts: Jest coverage HTML

Stage 4: E2E TESTS (Required)
  - Playwright: Chromium browser
  - Shards: 2 (parallel execution)
  - Full stack integration
  - Time: 10 minutes (total, 5 per shard)
  - Artifacts: HTML reports, JUnit XML

Stage 5: SMOKE TESTS (PR-only)
  - Backend smoke markers
  - E2E smoke tests
  - Time: 3 minutes
  - Purpose: Quick feedback for PR reviewers

Stage 6: TEST SUMMARY
  - Aggregate results
  - Slack notifications
  - GitHub summary
  - Time: 2 minutes

TEST MARKERS
================================================================================

Use these pytest markers to control test execution:

@pytest.mark.smoke              # Quick sanity check (included in smoke stage)
@pytest.mark.ai                 # Requires LLM (skipped in CI unit tests)
@pytest.mark.slow               # Long-running (skipped in CI unit tests)
@pytest.mark.requires_db        # Needs Postgres (skipped in unit tests)
@pytest.mark.requires_redis     # Needs Redis (skipped in unit tests)
@pytest.mark.requires_docker    # Needs Docker (skipped in unit tests)

UNIT TEST FILTER:
   -m "not ai and not slow and not requires_docker"

API TEST FILTER:
   -m "not ai"

================================================================================
TROUBLESHOOTING
================================================================================

ISSUE: "Frontend timeout"
SOLUTION:
   - Check Next.js build: cd apps/web && npm run build
   - Increase timeout in workflow file
   - Verify port 3000 is available

ISSUE: "Database connection refused"
SOLUTION:
   - Ensure PostgreSQL service is healthy
   - Check logs: docker logs <postgres-container>
   - Verify DATABASE_URL environment variable

ISSUE: "Playwright timeout"
SOLUTION:
   - Reduce E2E shard count (combine into 1)
   - Increase playwright timeout in config
   - Add explicit waits instead of sleeps

ISSUE: "Coverage < 70%"
SOLUTION:
   - Add more unit tests
   - Check coverage locally: cd backend && python -m pytest tests/unit/ --cov=app --cov-report=term-missing
   - Increase threshold if needed

ISSUE: "Slack notification not received"
SOLUTION:
   - Verify SLACK_WEBHOOK_URL secret exists
   - Test webhook manually with curl
   - Check channel has Slack app invited
   - Verify URL format: https://hooks.slack.com/services/...
