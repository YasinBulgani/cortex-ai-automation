 ARCHITECTURE
================================================================================

┌─ ReplicaHealthChecker ─────────────────────────────────────────────┐
│                                                                     │
│  Background async loop (every 30s):                               │

│    3. State machine: HEALTHY → DEGRADED → UNHEALTHY             │

│    5. Emit OTel spans: replica.health_check, state_change       │

                              ↓

│    4. Send webhook notification (optional)                        │
│    5. Emit OTel span: replica.failover                           │
│                                                                     │

================================================================================
 KEY FEATURES
================================================================================

✅ Automatic Health Monitoring
   - Async periodic checks (configurable interval, default 30s)
   - Replication lag measurement (PostgreSQL-specific)
   - Multi-replica support with priority ordering

✅ Intelligent State Machine
   - HEALTHY: lag < 500ms, connectivity OK
   - DEGRADED: lag 500-1000ms (warning logged)
   - UNHEALTHY: lag > 1000ms or connection failure
   - PROMOTED: replica now acting as primary

✅ Automatic Failover
   - Primary down → scan healthy replicas by priority
   - Promotion: connectivity test, retry with backoff
   - Switch connection pool to new primary
   - Webhook notification (ops team alert)

✅ Observable via OTel
   - replica.health_check: per-replica monitoring
   - replica.failover: promotion events
   - circuit.state_change: breaker transitions
   - All attributes: resource, state, lag_ms, duration_ms

✅ Three Failover Strategies
   - MANUAL: Health check logs, no automatic action
   - AUTOMATIC: Health check triggers promotion
   - HYBRID: Automatic for catastrophic, manual for degradation

✅ Thread-Safe Async Design
   - Non-blocking health checks (async event loop)
   - Thread-safe replica registry + state mutation
   - Graceful shutdown on app termination

================================================================================
 TROUBLESHOOTING QUICK-START
================================================================================

Issue: Health checker not starting
  → Verify: READ_REPLICA_ENABLED=true
  → Check: ReplicaHealthChecker.start() called in app.py
  → Logs: grep "Replica health checker started" app.log

Issue: Failover doesn't trigger
  → Verify: FAILOVER_STRATEGY=automatic
  → Check: Primary is actually unreachable (not just slow)
  → Logs: grep "UNHEALTHY\|FAILOVER" app.log

Issue: High OTel span volume
  → Reduce sampling: OTEL_SUCCESS_SAMPLE_RATE=0.01
  → Disable OTel: OTEL_SDK_DISABLED=true
  → Use adaptive: OTEL_SAMPLER=adaptive

Issue: Replica lag too high
  → Check: Network latency between primary + replica
  → Check: Replica DB resources (CPU / RAM / disk I/O)
  → Solution: Increase LAG_THRESHOLD_MS or add read-only load

================================================================================
 ROLLBACK PROCEDURE
================================================================================

If issues detected post-deployment:

Step 1: Disable Health Checker
  → Set: REPLICA_HEALTH_CHECK_ENABLED=false
  → Effect: Health monitoring stops, no automatic failover

Step 2: Disable Automatic Failover
  → Set: FAILOVER_STRATEGY=manual
  → Effect: Only admin-triggered failover allowed

Step 3: Revert to Single Primary
  → Set: READ_REPLICA_ENABLED=false
  → Effect: All reads + writes go to primary DB

Step 4: Verify OTel Silence
  → Grep logs: No "replica.failover" spans
  → Check: No "FAILOVER" messages in logs

Step 5: Monitor App Metrics
  → Observe: DB latency normalizes
  → Observe: No circuit breaker OPEN events
  → Confirm: App stability restored
